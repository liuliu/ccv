Causal floating-PV R/C crossover — 2026-10-11

Comparison: both variants use quantizePV=false, the same inputs and full
preparation. Original tiles: R16/C64/D64, 8 SIMD groups, output tile 128.
Candidate: R16/C32/D64, 4 SIMD groups, output tile 128.
Ratio = original time / candidate time: values below 1 mean a regression.
Bank retention is a separate comparison against quantizePV=true.
15 rotating samples, 300 ms GPU warmup; independent repeats use 31.
FP16, causal, dynamic R/C, B=1/Hq=8/Hk=2 unless stated otherwise.
All runs compare both outputs with the CPU reference (sampled on large inputs).

Selection
Use C32 / 4 groups for D>192, causal, unmasked, fixed-length floating PV when:
  2 * floor(R / 128) * B * Hq >= 3 * GPU_core_count, and C >= 4096.
The 128 is the original query threadgroup span: 16 rows * 8 SIMD groups.
Count complete groups before output-channel tiling. Partial groups do not
provide equivalent work: R=65/Hq=128 regresses substantially on the Mac,
despite a large count of 16-row query tiles.
The measured threshold is 1.5 complete query groups per GPU core. D>192 has
at least two output tiles, yielding at least three full threadgroups/core.
Use the same formula on both devices; retain original tiles if core count is
unknown. There is no precision-specific rule.
At B=1/Hq=8 the work bound means R>=1024 on the 40-core Mac and R>=256 on
the 10-core iPad. At Hq=16 these become R>=512 and R>=128 respectively.
More heads/batches can meet the bound at smaller R without a shape exception.

This is a conservative boundary around a broad crossover, not a guarantee
of a win at every larger shape. At B=1/Hq=8, the Mac odd-length R sweep
crosses around 896..1024; iPad crosses around 128..256. C transitions around
2048..4096. Scheduling and alignment produce local dips. Regressions remain
above the boundary (including FP32 outliers)
and are retained below, rather than excluded with length-specific rules.
Width/scope probes with D>192, R>=64 and C>=1024 had 46 wins / 11 losses on
Mac and 51 / 6 on iPad, including systematic small-R losses. These tile-choice
measurements support a query-work bound in addition to the head-width bound.

Reproduction
Build with build.py, then run check_crossover.py --sweep rc --samples 15
--probe /private/tmp/pv-repro/probe --output /private/tmp/pv-rc/PHASE
plus the flags below. Use a fresh directory per phase / precision /
specialization mode. For iPad add --device "$IPAD_DEVICE" --bundle BUNDLE.
Default RC sweep: D=256, B=1, Hq=8, Hk=2, FP16, dynamic=3, tails=0,1.
Each tail offset is added to both R and C; explicit coordinates with
--tails 0 allow independent row and column tails. R>C pairs are skipped.
