D256 causal inference, 2026-10-04

The source-corrected Local Code sweep exposed a causal prefill gap after the
noncausal register path was already integrated. The imported MLX kernel already
supports a causal function constant. The wrapper had disabled it and passed a
zero query offset. Retained integration enables it for D256 inference, passing
C-R as the offset so new queries are right-aligned with a growing KV cache.
Q remains in registers across KV tiles; two output slices reduce live state;
the causal traversal omits fully masked tiles. No storage transpose is added.

Selection retains R>64, FP16 IO, existing layouts, upcast/alias restrictions,
and excludes explicit masks, varlen, attention sinks and sliding windows.
Causal mode additionally requires inference, R<=C and C<=INT32_MAX-96. These
bounds avoid empty leading causal rows and overflow in padded tile arithmetic.
Causal is a pipeline constant/cache property. Only D generates kernel source;
shape, C-R and strides remain runtime parameters. Causal training is unchanged.
An INT8 preference uses the FP16 fallback here: INT8 output partitioning does
not implement causal masks. These rows are not INT8 arithmetic speedups.

GPU milliseconds, two reversed process orders, seven samples/order, at least
0.5 GPU seconds warmup. Actual MLX revision/build is recorded in handoff.txt.
