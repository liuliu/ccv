These are source-derived operator microbenchmarks, not whole-model timings or
captured activations. Text lengths and image/video dimensions are stated inputs
to the workload manifest, not claims about a universal application default.

RoPE, sampling, and CPU graph overhead are outside the measurements.

Timing and validation

Forward and projection measurements call the shipping MFA dispatchers. The
GEMM probe mirrors the dense frontend's M<=3 GEMV and low-K FP16 exception.
SmallM kernels, split-K reduction, attention split-KV reduction, activation
quantization and attention preparation are included when selected. Each job
warms for at least 0.1 GPU seconds, then records 25 GPU command-buffer samples
after at least 100 warmups. Very long video jobs use 30 warmups and 15 samples.
Two complete passes reverse execution order. The report uses the median of
pass medians, and retains both passes in CSV form.
Four cases with substantial launch-to-launch variation received three further
passes with at least one GPU second of warmup; these confirmations replace
their earlier timings in the summary. The final Wan projection rerun also
uses one GPU second. Each summary column identifies its source run and count.

MLX uses matmul and fast.scaled_dot_product_attention with normal FP16 inputs.
All unevaluated graph stages are timed when MLX lowers to several primitives.
The backward benchmark uses MLX's actual ScaledDotProductAttentionVJP, with
saved forward O/LSE materialized before timing, and measures all dQ/dK/dV.
The CCV backward probes use the validated production D64/D128 configurations.

Every CCV forward/projection output is checked for finiteness. Sampled outputs
are checked against a CPU reference using the unquantized FP16 inputs; INT8
errors therefore include quantization. MLX forward attention is also checked
against the same CPU formula. Backward dumps all three gradients in B/R/H/D
order, checks finiteness, and compares 16384 distributed values per gradient
against MLX. These deterministic inputs do not establish model-quality bounds.

FP16 IO does not imply identical accumulator precision between libraries.
The na and upcast matrix columns deliberately show both CCV contracts. MLX's
FP16 API is not an equivalent W8A8 matmul or INT8 attention operation.

MLX JIT correction

The original MLX checkout fails on causal D256 prefill (and the earlier D256
training-forward experiment). get_steel_attention_nax_kernel emits BV as a
template argument for attention_nax_dsplit, whose template has no BV argument.
mlx-dsplit-jit.patch omits this argument only for that specialization. A copy
of the JIT object and static library was built under /private/tmp; the checkout
was not modified. Patched measurements are explicitly identified. The patch
does not change tile selection, arithmetic, or the non-split specialization.
Original failures are retained rather than assigned timings.

Selector correction from the application sweep

The wide/deep FP16 GEMM tile regressed the large Wan MLP projection: approximately
53 ms versus 42 ms with the old 128x64x64 tile. Padding M from 32760 to 32768
did not fix it, and restoring split-K on the deep tile still took about 50 ms.
A 32768x18432x6144 Flux.2 projection also regressed, while the wide tile still
won at 9216x12288x3072, 32768x3072x3072, and 32768x4096x4096. Taller/deeper and
larger square candidates did not improve the large-output cases.

The final selector therefore bounds the wide/deep tile to 16384 output tiles
of 64x128, including batch (256 MiB of padded FP16 output). This is a conservative
measured footprint limit, not a claim about cache capacity or an exact crossover.
Larger footprints retain the original tile and split-K policy. No new hardware
check is introduced. Dynamic-M pipeline hashing and equality include the tile
choice as well as split-K. The randomized CPU-reference integration test crosses
that boundary in both directions at K512, where both policies use split-K=1.
It checks all GPU elements for finiteness and compares every column in 64
distributed rows against the CPU GEMM command, including first/last rows and
both sides of the 4096-row pointer boundary. Computing a full CPU reference for
these output footprints made the debug test impractical; the initial full-
reference test run was interrupted and is not counted as a successful suite.

The attention tile pilot did not justify a new production rule. At Wan's 20280
tokens, forcing C64 with 16 SIMD groups still took 154 ms; four groups took
122-127 ms, versus 24.7 ms for MLX and 19.2 ms for CCV INT8. The large floating-
point video-attention gap remains. These are pilot measurements, not a final
candidate sweep or evidence of a universal benefit from changing the selector.
