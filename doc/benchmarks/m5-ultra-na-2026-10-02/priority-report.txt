Long MiniMax H3 geometry
H3 uses 56 query and KV heads of D=128, hidden width 5376, Q/K/V width 7168,
FFN up/gate width 14336 and down width 5376, with 50 layers. Its exact attention
concatenates text, reference image/audio, audio and video tokens. The measured
long cases assume 256 text tokens, no references, and 810 audio tokens.
Requested 240 frames maps to 72 latent frames and 243 decoded frames through
LocalImageGenerator's temporal rounding and UNetProtocol's inverse mapping.
Video tokens = latent_frames * latent_height/2 * latent_width/2, with spatial
compression 16. Thus the patch-aligned proxies used here are:
  nominal 480p/10s: 832x480,  28080 video + 1066 conditioning = 29146 tokens
  nominal 720p/10s: 1280x736, 66240 video + 1066 conditioning = 67306 tokens
These dimensions are explicit proxies, not a claim that the UI emits exactly
these sizes: LocalImageGenerator constructs latent dimensions in multiples of
4 (64 decoded pixels), so the additional UI-rounded measurements use:
  832x512:  29952 video + 1066 conditioning = 31018 tokens
  1280x768: 69120 video + 1066 conditioning = 70186 tokens

What the investigations establish
1. Small sequence tails can change whole-kernel performance far beyond their
   arithmetic cost. At H3's 56 heads/D128, 14848x14848 takes about 68.4 ms;
   14864x14864 takes 399.5 ms and 14878x14878 takes 439.3 ms. Both query and
   key tails matter. This is observed code-generation/performance behavior;
   the exact compiler mechanism has not been established.
2. Changing tile C alone, Morton ordering, staging P in registers, fixed-width
   PV tail multiplication, or padded tensor-view extents did not recover parity.
   Several naive register-fragment prototypes were also slower than MLX.
3. An exact aligned-bulk plus small-edge decomposition removes most of the
   H3 FP16 gap while retaining S,H,D. 14878 tokens measured 70.2 ms (MLX 68.0).
   29146 tokens with generic MFA for the tiny KV edge measured 278.5 ms
   (MLX 270.4). Production confirmation (two reversed-order passes): 29146 tokens
   281.62 ms vs MLX 275.96; 67306 tokens 1677.44 ms vs MLX 1482.70.
   See priority-edge-confirmation.csv.
   The two partition outputs are weighted by their log2 softmax sums; this is
   exact attention decomposition, with the existing low-precision rounding.
4. The NA tiny-KV edge failed when supplied through one large sub-buffer offset;
   copying the same inputs into a fresh buffer passed. Generic MFA handled the
   original offset correctly. The implementation uses generic MFA for that
   small edge, without copying or transposing Q/K/V. The precise MPP offset
   issue still needs a minimal independent reproducer.
5. Quantization preparation is only a small fraction of long INT8 forward time.
   Reaching ~2x MLX requires improving the attention loop, not just its quantizer.
6. MLX D256 forward splits the head across SIMD groups and combines score
   partials. The register-attention follow-up now ports this kernel for
   noncausal FP16 attention directly on CCV SHD buffers, with no transpose.
   Causal Local Code prefill retains its existing implementation.
7. MLX VJP uses blocked GEMMs plus softmax/dS and gradient accumulation, with
   its own layout preparation included in timing. It is not simply the forward
   NAX kernel with derivatives. CCV needs a separate backward solution.
8. Deep projection K and large output footprints were matmul gaps. At H3's
   67306x5376x14336 down projection, FP16 is 179.3 ms and INT8 105.0 ms versus
   MLX 96.2 ms. Smaller image projections are closer, so a single tile rule
   should not be generalized from short square matrices.
   Follow-up INT8 row-range scheduling is now implemented for measured large
   working sets; see inference-followup.txt and its confirmation CSV. FP16
   projection chunking remains experimental because its crossover differs.

Current implementation and validation status
The register-attention follow-up supersedes the aligned-bulk/edge forward fix.
D128 and D256 unmasked/noncausal FP16 inference now use MLX-derived register
kernels directly on SHD buffers. D256 splits the head into two output slices.
There is no additional chip-name gate, tensor copy, partition merge, or extra
attention workspace. Causal, masked, variable-length, sink, upcast and other
precision/head-width cases keep their established paths.
The library cache keys the generated head width; pipeline constants encode
alignment and whether statistics are saved. All dimensions, strides and scale
are supplied at dispatch, including dynamic R/C. Saved LSE retains MFA's log2
half contract. The randomized CPU-reference regression covers ten shapes,
B2/GQA, dynamic shape reuse, D128/D256, aligned/uneven bounds, outputs and LSE.
The frozen previous binary and priority-edge-confirmation.csv retain the earlier
edge implementation's measurements for comparison. Latest validation and
production confirmation are in inference-followup.txt and priority-validation.txt.

A separate raw backward-probe issue was fixed: its threadgroup allocation return
type was uint16, so 96 KiB at D256/groups6 wrapped to 32 KiB. Allocation now uses
uint32 and staged group selection stays within 48 KiB (D128 retains groups6;
D256 uses groups3). Unsupported forced probe allocations are rejected. Production
already excluded NA D256 backward, so the invalid old raw result is not a
production regression or a valid MLX comparison. Corrected raw groups3 passed
an independent CPU gradient check but still trails MLX and is not dispatched.

Further implementation work, ordered by the requested priorities
Inference is the immediate priority. Further backward experiments are deferred.
- Close the remaining long H3 forward attention and projection gaps, including
  UI-rounded shapes. Retain S,H,D layout and time all preparation.
- Improve INT8 inner-loop reuse and accumulator placement; test long H3 first,
  then image MHA/GQA and D256. The wider C/D tile sweep did not improve H3.
  Query-register reuse improved the first pilot by less than 1%, which is not
  sufficient evidence for a production change.
- The register-attention follow-up now integrates the MLX-derived D128 and
  head-partitioned D256 forward kernels directly on S,H,D buffers. It replaces
  the edge-partition implementation and its extra workspace. See
  inference-followup.txt for the production confirmation and remaining gaps.
- Revisit long-K projection accumulation and data reuse on the actual H3 FFN
  dimensions. Distinguish FP16 accumulation and FP32-upcast contracts.
- Complete BF16 Qwen 2.1, float32-output projections, Sol exact/approximate
  routing, and sparse/sliding Local Code coverage; none is implied by the
  current dense FP16 tables.
