Inference integration: bounded INT8 output state and actual no-gradient graphs
2026-10-03

Implemented changes
Long-sequence D128 INT8 inference now splits KV into eight tile-aligned parts,
with no SHD/HSD conversion. Each part has its own FP32 V mean. Persistent output
state is one quarter of the normalized, centered weighted mean in FP16; row
maxima and normalization sums remain FP32. A fused FP32 rescale/PV update rounds
once to half. Partial outputs retain the factor of one quarter until the FP32
merge, avoiding intermediate half overflow even when a centered residual is
larger than a representable half value. The merge adds the separate V means,
weights the partials by FP32 log2 LSE, and writes O plus the graph's required
saved LSE in the existing half-prefix/log2 format.

Query chunks are at most 4096 rows and aligned to 64. Partial O plus FP32 LSE
storage is capped at 512 MiB independently of R. H56 uses 477,102,080 bytes;
H64 reduces the chunk to 4032 rows. Quantized inputs, scales, global LSE and
partition means are additional. Runtime ranges, partition sizes, chunk lengths,
and dispatch geometry are computed at encoding time. Only the source-changing
partitioned boolean enters the kernel-object cache; both descriptor layers
include it. The merge uses the normal cached library/pipeline/archive path.
No environment-variable selector or process-global pipeline is introduced.

Production selector
FP16 input/output with low-precision intermediates, INT8 preference, D128,
batch one, R >= 4096, C >= 24576, C*Hq >= 1,048,576, no causal mask, explicit
mask, packed variable lengths, sinks, or sliding window. At least one 64-row
chunk must fit the partial-buffer cap. Backward must not be required.
These bounds follow the 31-case crossover sweep (186 records), including
GQA and rectangular shapes. Hq counts aggregate traversal work; this is not
a physical KV-footprint/cache-capacity claim. There is no model-name or new
M5 Ultra name gate. Shorter C and lower head counts retain their faster route.
The C24576/H32 and H40 controls improve only ~1% or less; H48/H56 improve
8-9%. At C32768, H16/H24 regress while H32 and larger improve. C65536/H16
improves ~3%, H24 ~8%, H8 regresses. These outcomes motivated the joint bound.

Wide heads and Q/output reuse
Unmasked noncausal D256 inference with R>64 prefers the FP16 register kernel
over the current INT8 implementation when GEMM_8I is allowed. This follows the
25-case/150-record D256 sweep; it is an inference selection improvement, not a
2x INT8 throughput claim. Saved LSE no longer prevents inference selection.
Exact Q/O aliasing is also supported by register attention when K and V do not
share that buffer. A query tile writes its own rows after its last Q load.
Existing layout and signed-index bounds remain in force.

Why no-backward is separate from testing
Standard SDPA's command bitmask requires O and LSE even in a no-gradient model
graph. The earlier claim that CNNP pruning removes LSE was incorrect.
Furthermore Draw Things uses DynamicGraph.withNoGrad while the pinned Swift
Model.testing property defaults to false. Test-mode gating alone therefore
misses this application path. The final implementation adds the execution flag
CCV_NNC_NO_BACKWARD and passes it from ccv_cnnp_model_evaluate whenever
requires_grad is false. Both full-graph and scheduled evaluation propagate it
through the existing graph execution path. This does not change dropout/BN
is_test behavior. The MPS frontend passes it as MFA is_inference. Direct calls
with no LSE also qualify. Calls that require gradients keep the original INT8
V-centering/statistics contract. No model vtable or SDPA command-param field
was added in the final implementation. The paired application benchmark uses
ccv_nnc_dynamic_graph_set_no_grad with testing=false, matching Draw Things,
and compares it with a gradient-required CNNP forward control and actual MLX.

Remaining inference gaps and next implementation direction
The approximately 2x INT8 target is not achieved across the priority surface.
Long H3 attention is now close, but image D128 attention is 1.42-1.51x MLX and
D256 inference currently benefits from selecting FP16. Reaching 2x on the image
rows requires approximately 24-29% less time at D128 and 36% less at D256.
The eight-partition algorithm is not selected on these shorter sequences because
its partial writes, repeated query traversal and merge did not amortize there.
The next kernel investigation should separate QK/softmax/P-quantization time
from PV conversion and persistent-output updates, using arithmetic-preserving
diagnostics. A smaller live output state without the full partition workspace,
and sharing query/probability fragments across D256 output slices, are hypotheses
to test. They are not additional accepted gates or measured improvements.

Prior attempts at global INT32 output accumulation, explicit INT8 register
fragments, tile-local K/V staging and FP8 PV did not improve these workloads;
see inference-lowp-state.txt and inference-register-int8-prototypes.txt.
Blindly broadening the partition selector would repeat measured regressions.
No attention SHD-to-HSD conversion is planned. Backward optimization remains
deferred; the existing MLX VJP results are preserved in priority-report.txt.

The earlier projection work remains in the final library: NAMatMul's 32 priority
FP16 projection cases reach MLX parity (worst 1.6% slower at that checkpoint),
and NAInt8MatMul FFN-down is 1.77-2.44x MLX across the listed priority models.
H3 Q/up projections remain around 1.57-1.60x, another inference gap. Full shape
and error details are in inference-fp16-expanded.txt, inference-int8-register.txt
and inference-fp32-accumulator.txt. These are separate measured runs, not an
end-to-end model latency estimate. No rendered image/video validation was run.
