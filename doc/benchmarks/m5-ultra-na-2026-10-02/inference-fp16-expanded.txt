Comparison protocol
The production dispatcher, frozen preceding dispatcher, and actual MLX execute
serially in two opposite orders. Each pass uses three warmup iterations plus
at least 0.5 GPU seconds of warmup, then seven timed samples. Tables aggregate
the two GPU medians. Shader compilation and allocation are outside GPU timing.
Timing cases omit bias; fused bias is validated separately.
All matrices are FP16 A[M,K] and W[N,K]; the operation is A*W^T with FP16 output.
The new paths accumulate in FP32. Existing low-precision fallbacks may accumulate
in half. Each process checks every output for finiteness and compares sampled
entries against a CPU reference. Failed accuracy checks are retained as failures,
without an invented timing or speedup.

The manifest contains source-derived H3, FLUX.2, Krea 2, Ideogram 4, and Qwen Image
2.1 projections; surrounding row/channel/reduction/working-set controls; and both
fixed and dynamic M cases. The four additional UI H3 Q/up cases use 31018 and
70186 tokens. See priority-report.txt for frame, spatial and conditioning-token
assumptions and Draw Things source locations. Operator timings do not measure
whole-model generation, nor model output quality.

Implementations
1. Moderate reductions use MLX's explicit register-fragment GEMM. The existing
   64x128x512 profile is complemented by 128x64x512 with X/Y swizzle when N>M.
   Both use eight SIMD groups. This orientation matches MLX's Ultra tuning and
   matters on wide-output image projections. No new chip-name helper is added.
2. Wide outputs with deep reductions use MLX's partition-major split-K kernel.
   Each 4096-element K partition accumulates into FP32 scratch. A second kernel
   sums the partial outputs, adds optional broadcast bias, and stores FP16.
   The entire operation is timed. Its 1D grid preserves partition-major order;
   simply applying the regular register kernel did not recover these results.
3. The existing tensor-view split-K kernel added its global K remainder in
   every partition. It now assigns that remainder only to the last partition.
   K13824 with four partitions repeated 512 elements three extra times, explaining
   the approximately 11.1% relative error in the baseline. K8191/K12287 controls
   exposed the same error for dynamic remainder tiles. This is a correctness
   fix in the existing path, independent of the new hardware tuning.
4. The generic fallback uses FP32 accumulation for K>=65536. A correlated-input
   stress control exposed finite but grossly inaccurate half accumulation there.
   The new randomized positive-input regression exercises this boundary directly.

The register GEMM source is from MLX revision
25532871329fe4cafdada9fa0941a1cdbfb3a9f2 (MIT). The M5 Ultra tuning commit is
2d27ab05fb7dcda69bb3c57abd74c0b3bc9a5a99 (upstream PR #4447). See the local
3rdparty/mlx/README for imported headers, attribution, and the local epilogue.
The external comparison uses the documented isolated D256 JIT-signature patch;
no MLX GEMM arithmetic or tuning changes are included in that binary.

Measured selector
All new profiles reuse the existing M5 Ultra helper, and require contiguous NT
FP16 inputs/output, one batch, M>=4096 and N>=1536. Signed-index bounds also apply.
- Unsplit: 2048<=K<=8192, or 8192<K<=16384 with K<3*N, FP16 weights <=192 MiB, and either M<N or M>=2*N.
- Split-K takes precedence when M<N, K>=2*N, K<=32768 and each FP32 partial output
  is <=256 MiB. This bounds the partition count to eight and total scratch to 2 GiB.
- Other shapes retain their previous implementation, apart from the generic
  long-reduction accumulator precision fix.

The boundaries are empirical performance bounds, not claims about physical cache
sizes. The large-output/deep-K controls show why regular register GEMM should
not replace every existing path. Split-K instead helps when N>M, while long tall
outputs pay too much for its partial writes and reduction. Larger unmeasured
partial-output working sets remain on the existing dispatcher. There are no
model-name conditions. The original narrower register selector is superseded. The first expanded
selector regressed a 6144-square/K16384 control by about 24%; the final selector
retains the old implementation for deep square / moderately tall grids (N<=M<2*N).

Cache and scratch correctness
Tile orientation, integer/float operands, and split/unsplit traversal are shader
source properties and appear in both descriptor keys. Alignment and bias are
pipeline constants. All dimensions, strides, partition counts, swizzles and grid
sizes are current encode-time values. The second reduction pipeline is cached
with its bias setting. No shape-dependent dispatch is stored in the kernel object.
The device-independent scratch-reservation API conservatively covers both old
and new partial outputs; decoded palettized weights follow that reserved region.
It can over-reserve on other NA devices that keep the original profile; allocation
is needed only when that scratch is actually requested. The new split-K path
uses up to 2 GiB of FP32 partial outputs within its current bounds.

Discarded INT8 attention experiments
A per-head global centered-V scale would allow INT32 PV outputs to persist across
KV blocks and convert only at the end. In an isolated prototype, it regressed
H3 R14878 from 43.05 to 51.19 ms and R70186 from 1050.20 to 1216.11 ms. Changing
only the V quantizer while retaining float accumulation measured 44.09 and
1055.15 ms. Mapping the softmax coefficients through small integer aliases did
not recover throughput. At Ideogram D256/R4352, the INT32 version measured
5.71 ms versus current 5.63 ms, while global-V with float accumulation was 6.29 ms.
These changes are not retained. Deterministic sampled errors happened to match,
but that does not establish accuracy equivalence for the changed quantization.
No randomized quality claim is made for these rejected variants.

Removing the forward probability clamp after rint(P*127) was also measured in
two opposite orders, without changing the layout or scale rule. Sampled errors
were identical, but it did not provide a useful speedup:
  R=14878, D=128: current 43.173 ms; no clamp 43.262 ms.
  R=4352, D=256: current 5.630 ms; no clamp 5.598 ms.
  R=70186, D=128: current 1050.859 ms; no clamp 1062.364 ms.
It is not retained; raw results are in inference-int8-no-clamp-pilot.csv.
