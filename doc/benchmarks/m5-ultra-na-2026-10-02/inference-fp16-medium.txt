Medium-row FP16 inference dispatch, 2026-10-03

The register-GEMM minimum row count left measurable gaps at 768px image sizes
and Local Code prefill lengths. This checkpoint retains an accumulator-aware
extension of the existing dispatcher. Kernel source, tiling, the hardware helper,
attention layouts and INT8 selection are unchanged by this checkpoint.

GPU milliseconds below are medians of two reversed-order process medians.
All matrices use FP16 input, weights and GEMM output. acc=f32 explicitly requests
FP32 accumulation; acc=low permits the existing lower-precision path. The selected
register implementation accumulates in FP32 in both modes. cast=1 includes the
following Float32 conversion for every implementation. Timings exclude weight
decode and bias; decoded weights and bias are exercised by the regression.
Actual MLX runs from the local checkout; these are not estimates or peak-rate
comparisons. They are operator times, not whole-model generation speedups.

Retained rule and reasoning
Keep all previously selected M>=4096 cases. Within the existing contiguous NT,
one-batch FP16 IO support (N>=1536), additionally allow:
  - Explicit FP32 accumulator requests with M>=512.
  - Low-precision requests with M>=2048 and M*N>=4096*1536, except when the
    native wide MPP kernel has full N/K tiles (N divisible by 128, K by 512)
    and 2*N<=K<=8192. These compact moderate reductions retain the native path.
All preexisting unsplit K/aspect/weight-footprint limits and split-K rules remain.
Split-K still takes priority for M<N, K>=2*N, K<=32768 and <=256MiB per FP32
partial output. This also preserves the existing eight-partition / 2GiB bound.
The shared support helper is used for both encoding and decoded-weight scratch
reservation. Runtime dimensions and dispatch geometry remain encode-time values.

FP32 requests benefit from register fragments even on smaller grids. A blanket
extension of low-precision requests loses 8-10% on M512/N12288/K8192 and
M1024/N6144/K8192; an output-area bound alone does not protect those rows.
M3072/N2048,K8192 and M3072/N3072,K8192 also favor the native profile. The
retained mode/row/grid rule preserves those wins. Full-tile qualification matters:
neighboring irregular N/K shapes cannot use that native profile and benefit from
register fragments. These are measured bounds, not inferred physical cache sizes.
No model-name conditions or additional chip-name gate are introduced.

Simply enabling the unsplit register kernel is insufficient for wide deep FFNs.
For example the exploration measures FLUX.2 M2304/N6144/K18432 at approximately
4.47ms with split-K versus 6.02ms unsplit. Partition-major traversal and FP32
partial outputs contribute to the result beyond tile selection.
The imported register/split kernels and Ultra orientation derive from MLX PR
#4447, commit 2d27ab05fb7dcda69bb3c57abd74c0b3bc9a5a99. The local MIT
attribution is in lib/nnc/mfa/3rdparty/mlx/README. No new imported shader is added.

Coverage and validation
Exploration: 353 stage cases, 346 distinct requests, 286 distinct matrix shapes,
2,480 process records. Wide sweep: 221 cases / 1600 records; precision and
Local Code: 99 / 666; neighboring guard and repeat checks: 33 / 214.
Final retained-production comparison: 63 cases / 378 records, all passing.
Three warm iterations and at least .5 GPU seconds precede seven timed samples.
Processes run serially in opposite orders; no CPU compilation overlaps GPU work.
Every process checks all outputs for finiteness and 64 sampled values against
an independent CPU reference. Float32 casts are checked exactly against FP16
outputs. Different accumulation paths may change rounding; no bitwise identity
between old and new FP16 paths is claimed.
Full final MPSBLAS: 301/301. Full final MPSDNN: 126/126. Both exit 0 with the
expected success message. The GEMM regression now contains 50 cases, comparing
16 dispersed rows against CPU GEMM over all N columns at 3e-3 absolute tolerance.
It covers signed randomized tensors, prior positive stress cases, both accumulator
modes, row/area/K/N boundaries, partial tiles, bias, dynamic M, repeated cache
entries, and palettized weights after the enlarged FP32 split scratch region.
Existing source cases keep their previous flags and positive-input coverage.

Preserved failures and timing uncertainty
The precision exploration has six failed records, not six distinct shapes.
Both orders of the frozen baseline fail the 1% sampled relative-L2 limit at
M512/N12287/K24576 (1.1554%) and M512/N12289/K24576 (1.0620%). The broad
medium candidate also retains the latter native fallback and fails identically
in both orders. All outputs are finite. These explicitly low-precision stress
limitations remain outside the final extension, and are not valid speedup rows.
No tolerance was relaxed and no workaround is claimed for the odd-width cases.
All register-selected exploratory processes pass. The separate full randomized
regression provides stronger bias/tail/decode coverage than the timing probe.

One M1024/N2560/K9216 FP32 candidate record measured 0.82225ms instead of the
other order's 0.46537ms, giving an apparent 21.8% two-pass regression. Both
original records are preserved. A specifically labeled repeat measured 0.46671
and 0.46546ms; MLX was 0.46863 and 0.46413ms. The production table provides
another independent paired measurement. This report does not delete the slow
record or present every exploratory paired aggregate as non-regressing.

Remaining scope
The old deep-reduction aspect policy still leaves the Local Code Qwen 3.5 4B
M3072/N2560/K9216 case on its native FP32 path; its residual gap is shown above.
The broader unsplit prototype improves that case but regresses other measured
near-square low-precision cases, so that broader change is not retained here.
Small low-precision image shapes below the new row/area bounds remain on their
previous paths. This checkpoint does not assert parity for every possible shape.

The prior inference INT8 cast fusion remains integrated and validated; see
inference-fused-cast-integration.txt. Latest long H3 INT8 attention remains
1.94x / 2.09x actual MLX for exact UI 480p/10s and 720p/10s; the source and
protocol are in inference-probability-bounds.txt. Some image INT8 cases remain
below the approximately-2x goal. No new backward tuning or SHD-to-HSD attention
transpose is included. Earlier actual MLX VJP comparisons remain in
priority-report.txt. The wider goal stays open. Nothing is staged or committed.
