NAInt8MatMul production cleanup and Ultra follow-up, 2026-10-04

Parent: ece05fbcf6f798a400aba67542bb6a6b31ed0178 (m5-na-int8-matmul).
Baseline of this branch remains unstable 6a611be1. This is a follow-up to ece05fbc.

Changes
- One library, one createSource(), and one int8_matmul entry-point name.
  The library contains the shared activation quantizer and the selected multiply
  implementation. It no longer compiles an unused native multiply alongside
  a separate register library.
- Register scalar IO uses ioPrecision for scales, bias, and output. FP16, BF16,
  and FP32 use the same INT8 operands / INT32 reduction. H256 remains entirely
  in the existing activation quantizer. Its exclusion from register selection
  and the FP16-only restriction are removed; contiguous inputs/outputs and
  single-batch selection remain required.
- Preserve existing arithmetic compilation behavior: quantization retains its
  default math mode, and the multiply section has the existing safe math mode
  expressed as an MSL source pragma. There is no accumulator-format change.
- Medium-row selection now compares useful threadgroups between implementations.
  Let G64=ceil(M/64)*ceil(N/128), G128=ceil(M/128)*ceil(N/128), and C=GPU cores.
  The parallelism gate is G64 >= 2*C OR min(G64,C) > min(G128,C). Other size,
  reduction, core-count and address-range conditions are unchanged.
  At 512x2432x9216 on an 80-core profile, G64=152 and G128=76. The old 160-group
  floor rejected this case; the new comparison admits it. These counts model
  available independent work, not measured hardware occupancy or residency.
- New forward boundary cases and a --validate-register mode in the existing
  rotation validation harness cover the newly admitted support surface.

Scope
No attention, backward, native FP16 MatMul, fused-output-cast, or numerical
correctness fixes. The large-row partition policy is unchanged, including its
existing FP16 / non-H256 footprint guard; that guard is independent of register
kernel compatibility. No K-tail experiment is retained in production.

Remaining partial-column / K-tail issue (deferred to Ultra investigation)
The provided Ultra review measured 512x2559x9248 at 0.258 ms, versus unstable
0.238 ms and the prototype 0.210 ms; width 2560 was 0.124 ms. This update does
not claim to fix that gap. The Max also retains a column-alignment cliff:
512x2559x9248 is ~0.346 ms, while 512x2560x9248 is ~0.230 ms. Both dispatch
8x20 threadgroups; an extra column does not change the grid dimensions.

All 16 diagnostic calls passed CPU checks and matched hashes per shape,
with nominal thermal state. Specializing only K32 alignment, unrolling the
remainder by two, and separating its short fragment did not remove the cliff.
This does not establish a register-spill or instruction-level explanation.
The alignment-dependent generated path remains the investigation target.
The revised parallelism gate can also admit neighboring partial-column / K-tail
cases that previously used native tiles. Their Ultra profitability is unverified;
include 512x2431x9248 in the next round alongside aligned 2432 and K=9216.
The three diagnostic patches are supplied for optional Ultra experiments;
they are not included in the shipping kernel. See README.txt.
