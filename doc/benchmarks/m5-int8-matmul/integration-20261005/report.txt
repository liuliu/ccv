NAInt8MatMul integration review — 2026-10-05
Baseline: d8effcb21a778de4ba70c853b3d907b1d9093efb (m5-na-int8-matmul).
Hardware: M5 Max, 40 GPU cores. Final device validation: connected M5 iPad.

Implementation

Removed the imported 2,720-line GEMM source and all runtime string replacements.
The adapted fragment implementation is now explicit Metal code generated by
NAInt8MatMulKernel::createSource(). MLX Steel attribution and its MIT license are
retained in lib/nnc/mfa/3rdparty/mlx. No generic Steel GEMM entry point is used.

Both NAInt8MatMul implementations now bind packed A, packed B, C, A scales,
B scales and optional bias at indices 0 through 5. Runtime M uses the existing
loadM buffer; fixed M, N, K and batch strides use the existing function constants.
Removed the separate register encoder, 72-byte GEMMParams-compatible host struct,
and Steel-specific alignment/bias/batch function constants. Source objects do
not cache matrix shapes; dynamic-M register pipelines also reuse across alignment
and 4096-row boundaries. Native-only tile preferences and grouping do not create
extra register kernel variants. The kernel provides its full dispatch dimensions
through threadsPerThreadgroup(): (32,4,2) for register tiles; the native layout
remains one-dimensional. The existing threadgroupSize() count API is retained
for other native-only callers.

The retained mechanism is precise:
- One 16x16 fragment consists of eight values per lane: four adjacent columns in
  each of two rows eight apart. A SIMD group owns four fragments (32x32 output).
- Each K32 step loads 32x32 bytes from A and from B stored as [N,K]. Four
  M16/N32/K16 MPP operations update the four INT32 accumulator fragments.
  B's two N fragments are assembled into the transposed right operand.
- Eight SIMD groups form a 64x128 output tile. The K loop exposes pairs of K32
  updates and synchronizes the threadgroup every K512. Empty edge groups still
  reach every threadgroup barrier. Alignment decisions concern the entire
  64x128 tile, never individual SIMD groups. Explicit M/N divisibility predicates
  let constant dimensions eliminate tail code without extra alignment constants.
- Full K32 loads mask only rows on M/N tails. Only the final short K step masks
  both the row and the reduction coordinate. Scales, bias and scalar output
  conversion are applied after the INT32 reduction, as before.

The selector cleanup removes supports_tuned_matmul and useTunedMatMul. One
useRegisterMatMul decision separates layout/address constraints, device policy,
measured shape range, and useful parallelism. Native row partitioning uses that
same decision. Redundant family-1010 checks are removed: the existing neural-
accelerator capability flag already establishes that requirement.

This preserves the published selection policy. A standalone differential check
compiled the actual old/new predicates and compared 2,878,848 combinations of
boundary dimensions, core counts, layout, aliasing, rotation, scalar type and
NA availability. Register selection and row partitioning matched throughout the
valid NA capability contract.

Scope: NAInt8MatMul integration and selection cleanup. Attention, accumulator
precision, backward correctness and additional output-cast optimizations are
outside this change.

Regression isolation during integration

An initial rewrite flattened the register threadgroup from (32,4,2) to
(256,1,1), retaining the same 256 threads and logical output tile. That was not
performance-equivalent on this Max. At 4097x6144x18432 (including quantization):
  published d8effcb2             approximately 8.3-8.4 ms
  integrated shader, flat group approximately 11.1 ms
  same shader, original layout  8.596 ms
Output hashes were identical. Only changing launch geometry recovered most of
the loss. The final code preserves the full layout in the kernel API rather
than encoding a special launch outside the shared encoder. These timings
establish a dispatch-shape effect; they do not identify a particular hardware
cache or scheduler mechanism without GPU counter evidence.

Other controlled diagnostics did not recover the main gap: an initialized
volatile compiler fence (10.495 ms), explicit inlining with a flat group
(10.703 ms), runtime K inside the reduction (11.383 ms), original fragment
primitives (11.405 ms), and the original reduction function (10.629 ms).
The final implementation retains small inlined fragment primitives and the
original dispatch shape. It has no volatile fence, runtime-K workaround,
foreign parameter struct, imported GEMM entry point or textual source patching.

Remaining gaps

The partial-column regression is reproducible with both dynamic M (+3.30%)
and fixed M (+3.73%). Therefore dynamic-M pipeline sharing is not its sole
cause. The smaller mixed column/K-tail difference is +1.63% / +1.69%. The exact
compiler-level cause of these residual differences is not established. The
original substantial partial-column/K-tail cliff also remains: these results
do not establish parity with the paused Ultra prototype. Further Ultra timing
is needed for this integration, including these neighbors and the retained
large / H3 workloads. No new shape gating or fallback is introduced here.

iPad validation is pending: the final app built and installed successfully,
but iOS rejected its launch because the device was locked. The recorded launch
failure is an environment block; no iPad numerical or performance result has
been claimed for this update yet.
