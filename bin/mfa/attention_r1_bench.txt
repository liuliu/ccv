AttentionR1 decode benchmarks

Build from a CCV tree configured for MPS:
  make -C lib lib DEBUG=1 -j4
  make -C bin/mfa attention_r1_bench attention_r1_thermal

Production sweep (116 shapes, two reversed passes, 64 samples per process):
  python3 bin/mfa/attention_r1_sweep.py --list
  python3 bin/mfa/attention_r1_sweep.py --output /tmp/r1-fp16
  python3 bin/mfa/attention_r1_sweep.py --precision bf16 --output /tmp/r1-bf16
  python3 bin/mfa/attention_r1_sweep.py --id r2-c8192-h16-4-d256 --output /tmp/r1-one

The shape order is R, C, D, B, Hq, Hkv. The manifest covers both query lengths,
D128/D256, causal and noncausal requests, batches 1 through 16, MHA/GQA/MQA,
uneven lengths, direct/split boundaries, and KV lengths through 65536.
H16/Hkv4/D256 and H24/Hkv4/D256 are Local Code Qwen3.5 4B/9B and 27B
configurations (Libraries/SwiftLLM/Sources/Models/Qwen3_5.swift:58-80); other
shapes exercise dispatch and numerical coverage rather than specific models.
R1 and R2 model token decode and two-token speculative verification.

Each production timing includes the complete MFA attention dispatch. Inputs
and outputs use B/S/H/D storage; there is no explicit layout transpose.
Compilation, allocation, initialization, output hashing and CPU checking are
outside the GPU timestamps. Each process uses at least two GPU seconds of
warmup as well as three iterations. Shorter warmups have produced slower
first-stage timing modes on this host. Never compile or run another GPU job
concurrently with a timed sweep. Metal execution requires GPU access.

The runner checks nominal thermal state before and after each process, keeps
all raw samples and exact commands, records source/binary hashes and machine
information, and exits nonzero for numerical failures or baseline regressions
above both 5 percent and 2 microseconds. A failed/incomplete run is not evidence
of a passing comparison. Output directories must be new; deliberate reruns
preserve prior evidence. Across machines, compare against that machine's MLX,
not fixed Ultra timings.

Save a statically linked attention_r1_bench before rebuilding to compare:
  python3 bin/mfa/attention_r1_sweep.py --baseline /path/to/saved-probe \
    --output /tmp/r1-paired

--mlx accepts the actual-MLX C++ comparison probe CLI (mlx_na_bench.cpp), as
archived with this change's benchmark report. It evaluates MLX SDPA, not a
reimplementation. Use FP16 for these comparisons. Its inputs differ from this
standalone randomized probe, but each output is independently CPU-checked.
The report's paired measurements use the same deterministic input fixture for
both implementations. Preserve the recorded MLX revision and any JIT patch
when reproducing those results. MLX_SDPA_* overrides are cleared by the runner.

Standalone example:
  bin/mfa/attention_r1_bench 2 8192 256 1 16 4 3 64 1 3

Arguments:
  R C D B Hq Hkv warmup samples causal dynamic_flags
  [precision] [profile] [partitions] [reduce_simds] [heads_per_group] [direct_simds] [heads_per_simd]

precision: 0=FP16, 1=BF16. dynamic_flags: bit 0 disables M specialization;
bit 1 disables C specialization. CCV_NA_WARMUP_SECONDS overrides the minimum
warmup. The normal dispatcher controls production selection regardless of
profiling overrides. profile=1 additionally times the selected override and,
for split kernels, each stage separately. For example:
  bin/mfa/attention_r1_bench 2 8192 256 1 16 4 3 64 1 3 0 1 128 16

A nonzero direct_simds profiles the cooperative direct kernel and cannot be
combined with partitions, heads_per_group or heads_per_simd.
heads_per_simd=1 or 2 profiles independent or paired GQA heads; the logical
head group must be divisible by this value and stay within one KV head. Stage timings diagnose bottlenecks;
they are not additive, and must not be compared with a complete MLX operation.
Only production timing represents the normal dispatch policy.

The probe fills randomized inputs, scans the entire output for finiteness,
hashes the output and checks selected positions against double-precision CPU
attention. Full-output randomized CPU comparisons, in-place/offset guards,
cache transitions and sinks are covered by the mpsblas integration tests:
  ./mpsblas.tests "decode cache transitions"
  ./mpsblas.tests "R2 mps decode with attention sinks"
  ./mpsblas.tests "decode preserves saved logsumexp"
  ./mpsblas.tests "NA mps splitKV decode"
  ./mpsblas.tests "BF16 R1 mps decode"
